# 模擬器驗證

裝置測試僅在可拋棄的專用 Android 模擬器執行。實體手機安裝與完整互動驗證是分開的步驟；安裝成功不代表鎖定、感測器或 OEM 行為已驗證。

## 測試環境

- Android API 35、Google APIs、x86_64。
- 1280 × 720 橫向顯示、320 dpi，固定螢幕旋轉。
- 啟用硬體加速，關閉動畫與首次全螢幕提示干擾。
- 使用專用 AVD、獨立 Android 使用者資料與明確指定的 ADB server／emulator serial。
- 每次操作前核對 AVD、開機完成、API 版本及模擬器身分；任何不符即停止。

本機有實體裝置連線時，不得對未限定裝置的 ADB 目標執行測試。不得以實體裝置代替失敗或未啟動的模擬器。

## 自動化覆蓋

JVM 測試涵蓋感測向量、鎖定期限、狀態保存、版面幾何、偏好遷移、媒體進度與低電量政策。Android 測試涵蓋實際 Compose 畫面、拖曳與手勢、Android MediaSession、行事曆、低電量、閒置關屏及防烙印渲染。

媒體測試使用程式建立的工作階段、封面及文字，不讀取私人音樂資料。行事曆測試使用合成資料。PixelCopy 檢查封面、進度點與防烙印像素，不能推論 OLED 長期耐久性。

`scripts/verify-background-clock.py` 另外檢查四個行為：

1. 從背景鎖定後顯示取得焦點的時鐘。
2. 設定重建後工作階段仍有效。
3. 退出後同一次鎖定週期不重新啟動。
4. 下一次鎖定可再次啟動，不需重新開啟主畫面。

會使用螢幕關閉、媒體控制或裝置管理員的測試，必須先通過專用模擬器檢查，並在結束後清除暫時狀態。

## 結果要求

完整執行需同時檢查預期測試總數、零失敗／錯誤／跳過、正常 instrumentation 結束，以及四項背景行為結果。不得將截圖狀態事件當成通過測試，也不得將缺少報告、逾時或取消當成成功。

原始 log、視窗狀態、APK、測試截圖與裝置診斷置於忽略的 `.local/`，公開說明只保留去識別化摘要。
