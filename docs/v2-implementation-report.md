# LinzinDeskClock 2.0.4 實作說明

## 功能與架構

保留既有錶盤、配色、月曆與天氣。將設定、時鐘畫面、感測器、媒體、電量及鎖定生命週期拆為獨立元件，避免主 Activity 持續擴大。

- 一般手機使用重力感測／加速度計備援，確認實體橫放及相對桌面 30°–75° 傾角。只有鎖定事件啟動最多 5 秒的掃描，條件需連續穩定 1.5 秒。
- 摺疊機鉸鏈 30°–120° 觸發與一般手機傾角分開處理。
- 背景監看由使用者啟用的前景服務維持。從其他 App 鎖定後自動開啟須另行授予 Android 特殊存取權；無權限或 OEM 阻擋時保留通知備援。
- 鎖定週期、一次性開啟 token、退出抑制與開機識別同步保存，避免程序重建、手動退出或逾時後重複喚醒。
- 雙面板可拖曳 20%–80%，放開時支援 30／50／70% 吸附。時鐘側別由使用者選擇，與比例分別保存。
- MediaSession 元件處理權限、工作階段與媒體回呼；只使用內嵌封面 Bitmap 與有界快取，不任意下載 metadata URI。鎖定畫面保留曲名、封面、進度及已授權控制，UI Lock 另外停用互動。
- 行程摘要可開啟詳細資訊，外部行事曆連結包含正確 occurrence 時間；鎖定、撤權或資料失效時清理詳細資料。
- 低電量保護可降亮度或退出，只調整時鐘視窗亮度。防烙印涵蓋媒體控制區。
- 有限閒置逾時會要求真正關屏；選用裝置管理員只宣告 force-lock。未授權或 API 失敗時退出並釋放保持喚醒，交由系統逾時處理。

## 權限

通知存取供 MediaSession 使用；通知、前景服務與 specialUse 類型供明確啟用的監看使用。SYSTEM_ALERT_WINDOW 是選用的背景 Activity 啟動授權，程式不建立覆蓋視窗。裝置管理員另由系統同意畫面授權，僅包含鎖定政策。DreamService 與通知監聽器均有系統 bind permission 保護。

沒有新增無障礙服務、root、Shizuku 或解除系統 keyguard 的機制。安裝 APK 不會自動授予上述特殊權限。

## 驗證與限制

完整測試分為 JVM、lint、API 35 instrumentation 及四項背景啟動檢查。每次整合以實際 commit 與測試結果為準，不能沿用其他來源版本的通過狀態。測試命令與條件見 [建置環境](build-environment.md) 及 [模擬器驗證](emulator-testing.md)。

模擬器驗證無法保證所有 OEM 的熄屏感測、背景啟動、外螢幕指令、螢幕保護程式或媒體提供者行為。手動檢查項目見 [真機驗收清單](v2-device-checklist.md)。
