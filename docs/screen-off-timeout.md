# 閒置關屏（2.0.4）

有限閒置逾時會結束時鐘，並透過 DevicePolicyManager.lockNow() 要求真正的系統鎖定與關屏。原有黑色覆蓋及亮度歸零的假休眠已移除；低電量降亮度是獨立政策。

## 啟用

在時鐘設定選擇有限逾時，再點擊選用的「僅鎖定」裝置管理員按鈕，於 Android 系統同意畫面授權。receiver 只宣告 force-lock，沒有抹除資料或變更密碼政策。安裝及逾時回呼都不會代為授權。

系統鎖定後可能要求 PIN、圖案或密碼，不能保證立即使用生物辨識。未設定安全鎖定的裝置不會因此新增密碼。可從系統裝置管理員設定停用授權。

未授權、不支援、授權已撤回或鎖定失敗時，時鐘會退出並釋放保持喚醒，提示改由系統逾時關屏；此備援不保證立即熄屏。

## 生命週期

- 所有有限逾時都等待完整設定時間，觸控會重新計時。
- 設定視窗、權限頁面及背景狀態暫停計時，返回後重新計時。
- MainActivity、ClockSessionActivity 與 ClockDreamService 各自清理 host 狀態；先保存退出抑制、取消通知備援並釋放喚醒 flags，再要求鎖定。
- 被動前景／亮屏觀察不清除抑制；實際解鎖，或已解鎖且互動中的明確使用者入口，才能恢復下一次鎖定監看。
- 時鐘側別、比例、媒體、防烙印及摺疊觸發範圍維持原選擇。

## 驗證

ScreenOffTimeoutTest 驗證實際 Compose 計時、互動、設定與生命週期；ScreenOffSystemTest 驗證 receiver 政策、未授權備援及 PowerManager 非互動狀態，並觀察完整 5 秒啟動視窗不會重新喚醒。測試僅在通過身分檢查的專用模擬器執行，暫時管理員授權在 finally 清除。
